> 이 파일은 **단독 실행 가능한 작업지시서**다. 그대로 복사해 붙여넣으면 된다.
> **시작 전 [RULES.md](RULES.md) 를 먼저 읽을 것** — 건드리면 안 되는 것들이 있다.

- **난이도/소요**: Small. ~20 minutes hands-on: two contiguous find/replace edits (one per file), plus ~5 minutes running verification steps 1–4, plus ~5–8 minutes of deploy wall-clock. No new dependencies, no schema migration, no data backfill, no native code. The only non-trivial part is typing the sanitizeTelemetry helper exactly; verification step 1 catches any typo in it immediately.
- **배포 필요**: YES — two deploys, in this order:

  1. Backend (required, for functions/index.js):
       cd /Users/mark/repos/Snakeball && firebase deploy --only functions
     Note this redeploys ALL functions in the project (the money-path functions included,
     unchanged). Their secrets are already configured in production, so no secret setup is
     needed. Wait for it to report success before step 2.

  2. Web client (required, for index.html):
       cd /Users/mark/repos/Snakeball && npm run deploy:web
     This runs `sync:public` + `firebase deploy --only hosting` + `deploy:rules`. The rules
     deploy is a no-op here because firestore.rules is unchanged — that is expected and fine.

NOT required:
  - No native rebuild. The iOS (WKWebView) and Android (WebView) shells load the hosted URL,
    so the client change reaches them the moment hosting is deployed. No App Store or Play
    review needed.
  - No separate `firebase deploy --only firestore:rules` beyond what deploy:web already does.
  - No Toss redeploy is strictly required for correctness, but `npm run toss:build && npm run
    toss:deploy` is needed before Toss runs will report platform:"toss" (the Toss bundle is
    built from index.html, not loaded from hosting). Do this whenever the next Toss build ships.

Order matters only mildly: deploying functions first means no window in which a client sends
telemetry to a server that ignores it. Callable functions ignore unknown request.data fields,
so the reverse order is safe too — it just produces a few minutes of "unknown" sessions.

/**
 * 런 텔레메트리(platform/appVersion) 정리 — 클라 문자열을 문서에 그대로 쓰지 않기 위한 관문.

 * 서버 문서에 심을 수 있게 된다(문서 비대화 + 집계/대시보드 오염). 그래서 여기서 좁힌다:
 *   - platform  : 허용 목록에 없는 값은 전부 "unknown" (자유 문자열 금지)
 *   - appVersion: 버전에 쓰이는 문자만 남기고 16자에서 컷
 *
 * sanitizeName 과 달리 **절대 throw 하지 않는다.** 텔레메트리는 부가정보일 뿐이고,
 * 여기서 던지면 세션 발급이 실패해 게임이 리더보드 없이 돌게 된다. 이상값은 "unknown".
 * 상수를 함수 안에 둔 이유: firebase-admin 부팅 없이 이 함수만 떼어내 단위검증할 수 있게.
 */
function sanitizeTelemetry(raw) {
  const ALLOWED_PLATFORMS = ["ios", "android", "toss", "web"];
  const APP_VERSION_MAX_LEN = 16;
  const src = raw && typeof raw === "object" ? raw : {};
  const platform = ALLOWED_PLATFORMS.includes(src.platform) ? src.platform : "unknown";
  let appVersion = "unknown";
  if (typeof src.appVersion === "string") {
    const cleaned = src.appVersion
      .trim()
      .replace(/[^0-9A-Za-z._+-]/g, "")
      .slice(0, APP_VERSION_MAX_LEN);
    if (cleaned.length > 0) appVersion = cleaned;
  }
  return { platform, appVersion };
}

/**
 * startRun — 게임 시작 시 세션 발급 (안티치트 앵커).
 * 입력: { platform?, appVersion? } — 텔레메트리 전용(선택). 누락/이상값이면 "unknown".
 * game_sessions/{token} = { uid, startedAt, used:false, platform, appVersion } 생성.
 * 반환: { sessionToken }.  ← 반환 shape 은 계약이다. 절대 바꾸지 말 것.
 */
exports.startRun = onCall({ region: REGION, minInstances: 0 }, async (request) => {
  if (!request.auth) {
    throw new HttpsError("unauthenticated", "인증이 필요합니다.");
  }
  const uid = request.auth.uid;

  // 채널/버전 태깅 — iOS/Android/Toss/Web 4개 채널로 동시에 나가면, 사후에 "이 런이 어느
  // 채널·어느 버전에서 나왔는지"를 복원할 방법이 없다(백필 불가). 붙일 수 있는 유일한
  // 지점이 세션 발급 시점이라 여기서 기록한다. 클라 문자열은 신뢰하지 않는다.
  const telemetry = sanitizeTelemetry(request.data);

  // 랜덤 토큰 = Firestore auto-id.
  const sessionRef = db.collection("game_sessions").doc();
  await sessionRef.set({
    uid,
    startedAt: FieldValue.serverTimestamp(),
    used: false,
    // ↓ 순수 텔레메트리 필드. submitScore 의 안티치트 판정과 coinSystem 의 revive 카운터는
    //   이 값을 절대 읽지 않는다(읽게 만들지도 말 것). 추가 전용 필드다.
    platform: telemetry.platform,
    appVersion: telemetry.appVersion,
  });

  return { sessionToken: sessionRef.id };
});

## 6. 리스크

1. Deploying functions redeploys the whole functions codebase, including the IAP/coin money
   path, even though those files are unchanged. Low risk (identical code, secrets already set)
   but it is a production deploy — do it when you can watch the Cloud Functions logs for a
   few minutes afterwards.

2. Cached old clients. Players already holding a cached index.html will keep calling startRun
   with no arguments until their WebView/browser picks up the new hosting build. Those sessions
   land as platform:"unknown", appVersion:"unknown". This is expected and self-healing; do not
   "fix" it by making the server guess from the User-Agent.

3. Document size / cost. Two short string fields per session document. Negligible, and the
   16-char cap plus the platform allow-list is exactly what stops a malicious client from
   inflating those documents.

4. `platform` is a Firestore field name, not a reserved word, and does not collide with any
   existing field on game_sessions (uid, startedAt, used, reviveCount). Verified.

5. Telemetry is intentionally best-effort: sanitizeTelemetry never throws, so a malformed
   payload degrades to "unknown" rather than failing session issuance. If a future change makes
   it throw, every run silently loses its leaderboard session — keep it throw-free.

6. Analytics caveat worth writing down for whoever reads the data later: platform is what the
   CLIENT detected (webkit.messageHandlers / AndroidBridge / ReactNativeWebView presence), not
   an independently verified channel. It is good enough to segment retention and crash-adjacent
   metrics; it is NOT evidence for anything adversarial (a determined client can still claim
   any of the four allowed values). Do not use it as a gate on rewards or purchases.

7. If verification step 1 cannot locate the end of the helper, the implementer probably
   reformatted it so a closing brace sits at column 0 inside the function. Re-paste the helper
   verbatim rather than adjusting the verification script.


## 7. 커밋 메시지

```
telemetry: tag every game session with platform + app version

startRun wrote only {uid, startedAt, used} to game_sessions and the client called it with no arguments, so once the game ships to four channels (iOS, Android, Toss, Web) there was no way to tell an iOS run from a Toss run, or a v1.0 run from a v1.0.1 run — and because a session document is created once at run start and never revisited, this could never be backfilled after the fact. The client now passes { platform, appVersion } from the values it already has (detectPlatform() and the APP_VERSION constant), and the server passes them through a new sanitizeTelemetry() helper before persisting them: platform is narrowed to an allow-list of ios/android/toss/web (anything else becomes "unknown") and appVersion is stripped to version-safe characters and capped at 16, so an untrusted client string never lands in a Firestore document verbatim. The helper deliberately never throws — telemetry must not be able to fail a session issue and silently drop the player off the leaderboard — so missing or malformed input degrades to "unknown". The change is strictly additive: startRun's return shape ({ sessionToken }) and the session-token contract are untouched, the existing uid/startedAt/used fields keep their names and values, and neither the submitScore anti-cheat bound nor coinSystem's revive counter reads the new fields.
```
